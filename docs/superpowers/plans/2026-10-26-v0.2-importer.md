# v0.2 PyRIT Dataset Importer (Phase 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `suite import` command that turns PyRIT's garak `system_prompt_extraction` dataset into a git-ignored OWASP-LLM07 baseline pack, runnable through the existing pipeline, with `--pack` made repeatable so the baseline composes with the owner's own prompts.

**Architecture:** Four small units reuse v0.1's `Prompt`/`Pack`/`Checks` and detectors. `adapters/datasets.py` (the only new pyrit importer) loads a garak dataset via `SeedDataset.from_yaml_file`; `importer_map.py` is the committed dataset→OWASP mapping; `importer.py` applies it and writes pack YAML + `COVERAGE.md` deterministically; `cli.py` adds `suite import` and a repeatable `--pack`.

**Tech Stack:** Python 3.13, uv, `pyrit==1.1.0` (behind `adapters/` only), pydantic v2, PyYAML.

**Spec:** `docs/specs/2026-10-26-v0.2-importer-design.md` (read §1 Phasing and §5 — this plan is **Phase 1** only).

## Global Constraints

- Python `>=3.13`; `pyrit==1.1.0`; **only files under `src/suite/adapters/` may import `pyrit`** (enforced by `tests/test_boundary.py`).
- **No attack text in the repo or tests.** The importer moves garak's text file→file; tests use a **benign fixture dataset** (`tests/fixtures/garak/*.prompt`) authored with placeholder prompts.
- Judging stays deterministic; **Inconclusive / needs-review is never a Pass**. A prompt with no check routes to review.
- No network in `import` or in tests. `suite import` loads pyrit lazily; `validate`/`finalize`/`compare` stay pyrit-free.
- Generated output is git-ignored (`prompts/baseline/`); the mapping table and importer code are committed.
- Deterministic output: same inputs → byte-identical files. Writes are atomic (temp file + `os.replace`).
- OWASP codes and `DETECTOR_NAMES` come from `suite.prompts` (`OWASP_LLM_2025`, `DETECTOR_NAMES`); `credential_leak` is already wired. **Phase 1 adds no new detector.**
- Never run `git checkout/reset/restore/clean/stash`; TDD (failing test first); commit per task on branch `feat/v0.2-importer`; end commit messages with `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`.

## Review Focus

1. **`--canary` absent** → extraction prompts still carry the `credential_leak` detector, so they are judged, not silently passed; only a prompt that ends with zero checks goes to review. → Task 3 `test_without_canary_keeps_credential_leak`.
2. **Re-running `suite import`** → byte-identical files (stable ids, sorted, fixed YAML style); no churn, no partial file on failure. → Task 3 `test_import_is_deterministic`, `test_write_is_atomic`.
3. **A garak prompt whose text breaks our `Prompt` rules** (empty, or a value that trips validation) → surfaces with dataset + index, never silently dropped or written. → Task 3 `test_unloadable_prompt_is_reported`.
4. **Duplicate prompt id across two `--pack` paths** → `ConfigError` naming both packs, nothing run. → Task 4 `test_duplicate_id_across_packs_is_rejected`.
5. **`suite import` / `validate` / `finalize` / `compare` must not import pyrit** except `import`'s own path; the boundary test covers the new `adapters/datasets.py` automatically. → Task 5 `test_import_help_is_pyrit_free` (subprocess, `validate`).

**Interfaces:**
- Consumes: PyRIT `SeedDataset.from_yaml_file` (`from pyrit.models import SeedDataset`), and `pyrit.__file__` to locate bundled datasets.
- Produces:
  - `GARAK_DIR: Path` = `Path(pyrit.__file__).parent / "datasets/seed_datasets/local/garak"`.

A missing file, an unparsable file, or a dataset with zero seeds raises `ConfigError` naming the file. No `init_pyrit()` needed (loading a dataset touches no memory).

### Task 3: the importer (`importer.py`)

**Files:**
- Create: `src/suite/importer.py`
- Test: `tests/test_importer.py`

**Interfaces:**
- Consumes: `load_garak_dataset`/`DatasetPrompt` (Task 1), `GARAK_MAP`/`MapRow`/`COVERED` (Task 2), `suite.prompts.Prompt`/`Checks`/`Pack`/`load_pack`, `suite.models.ConfigError`.
- Produces:
  - `@dataclass(frozen=True) ImportResult(out_dir: Path, files: list[Path], prompt_count: int, categories: list[str])`.
  - `def build_prompts(rows: list[DatasetPrompt], row_map: MapRow, *, canary: str | None, repeat: int) -> list[Prompt]`. For each `DatasetPrompt`: `id = f"BASE-{row_map.category}-{row_map.dataset}-{index+1:03d}"`; `category = row_map.category`; `prompt = text`; `repeat = repeat`; `checks = Checks(detectors=list(row_map.detectors), must_not_contain=[canary] if (row_map.canary_check and canary) else [])`; `pass_if = row_map.default_pass_if`. Each built `Prompt` is `model_validate`-d; a failure raises `ConfigError` naming the dataset + index.
  - `def import_source(source: str, out_dir: Path, *, canary: str | None, repeat: int = 1, base_dir: Path = GARAK_DIR) -> ImportResult`. `source` must be `"garak"` (else `ConfigError`). For each dataset in `GARAK_MAP`: load rows, build prompts, group by category. Write one `prompts/<out_dir>/<CATEGORY>.yaml` per category (a header comment naming source=garak via PyRIT, Apache-2.0, "git-ignored — regenerate, don't edit", then the prompt list) and `COVERAGE.md` from `COVERED`. Writes are atomic. A `--canary` shorter than `MIN_CONTAIN_CHARS` letters/digits raises `ConfigError`. After writing, `load_pack(out_dir)` must succeed (the importer's own output is a valid pack) — assert this in-process and raise if not.
  - YAML style fixed: `yaml.safe_dump(data, sort_keys=False, allow_unicode=True, default_flow_style=False, width=4096)`; prompts in id order; so re-runs are byte-identical.

- [ ] **Step 1: Write the failing tests** (drive from the benign fixture via `base_dir`; use a fixture-only map or monkeypatch `GARAK_MAP` to point at `fixture_extraction` so no garak text is needed).

### Task 4: repeatable `--pack` (merge packs)

- Modify: `src/suite/cli.py` (`_add_endpoint_and_pack`, `_plan`)

**Interfaces:**
- Produces: `def load_packs(paths: Sequence[Path]) -> Pack`. Loads each path with `load_pack`, concatenates prompts in argument order, and raises `ConfigError` for a prompt id duplicated **across** packs (message names both source paths). The merged pack's `name` is the paths joined by `+`. A single path behaves exactly like `load_pack`.

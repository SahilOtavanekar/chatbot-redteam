# v0.4 Web UI (Read + Review) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A localhost web UI that lets the operator browse runs and OWASP reports, see coverage, compare runs, and do the human-review step in the browser — a thin layer over the existing engine.

**Architecture:** One service layer (`src/suite/web/service.py`) is the only web module that reads `results/` and calls the engine (`build_report_data`, `finalize`, `compare_runs`, `read_run_json`). A JSON API router and an HTMX/Jinja2 views router are two faces over that one service. The engine does not change; `web/ → suite/` is one-way.

**Tech Stack:** FastAPI, Uvicorn, Jinja2 (already a dep), HTMX (vendored), SQLite/stdlib via the engine. Python 3.13, pytest + FastAPI `TestClient` (no network).

**Spec:** `docs/specs/2026-10-27-v0.4-ui-design.md`

## Global Constraints

- Python `>=3.13`; ruff `line-length = 100`, lint `E,F,I,UP,B,SIM`; mypy `disallow_untyped_defs` over `src`. Every `def` in `src/suite/web/` is fully typed.
- **TDD under `src/`:** write the failing test, watch it fail, then implement.
- **Engine unchanged.** No edits under `src/suite/` except `cli.py` (new `web` subcommand) and `pyproject.toml` (deps). All new code lives in `src/suite/web/`.
- **Single engine importer:** only `src/suite/web/service.py` imports the engine's data functions (`suite.report`, `suite.review`, `suite.compare`, `suite.evidence`, `suite.prompts`). `api.py`, `views.py`, `app.py`, `settings.py` import only `suite.web.*` and third-party libs. A boundary test enforces this (Task 8).
- **Redacted text only.** The web layer never reads raw `reply_text` from `evidence.db`. Everything shown comes through `build_report_data` (redaction gated on `run["redact"]`) or the run's `review.csv` (already redacted when written).
- **Replies stay inert.** Jinja2 autoescape is on for HTML templates; nothing is marked `safe`.
- **No secrets rendered.** Run facts show only the endpoint *name* (`report.run_facts` already limits this); never the endpoint block or any `.env` value.
- **Path safety:** a run id must resolve to a direct child directory of `results_dir`; anything else is a 404. Never join an id into a path without that check.
- **Local-only default:** server binds `127.0.0.1`; no auth. Binding elsewhere prints a one-line no-auth warning.
- **Atomic writes:** `review.csv` is rewritten via temp file + `os.replace`, `utf-8-sig`, `newline=""`, matching the engine's style.
- **Dependencies pinned/added in `pyproject.toml`:** add `fastapi` to runtime deps; move `uvicorn` from `dev` to runtime. Vendor `htmx.min.js` locally (no CDN).

## Review Focus

- **Path-traversal run id** (`../`, an absolute path, a sibling file not a directory) → 404, never a read outside `results_dir`. Test in Task 1 (`resolve_run_dir`) and Task 6 (API 404).
- **Run folder missing `run.json` or `evidence.db`** → listed as unreadable (Task 1) and 404 on detail (Task 2), never a 500 (API test Task 6).
- **Reply containing `<script>`/HTML** → rendered escaped (inert), not executed. Test in Task 7 (views).
- **Finalize on a bad or locked `review.csv`** → the engine's `ConfigError` text is surfaced, nothing half-applied, no 500. Test in Task 5 (`finalize_run`) and Task 6 (API).
- **Review note starting like a spreadsheet formula** (`=SUM...`) → neutralised with `csv_cell` on write so `review.csv` stays safe and `finalize` round-trips it. Test in Task 5 (`set_review_verdict`).

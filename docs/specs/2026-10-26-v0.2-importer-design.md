# chatbot-redteam v0.2 — PyRIT dataset importer (OWASP baseline)

Date: 2026-10-26
Status: draft for review
Author: Sahil Otavanekar (with Claude)

Builds on the v0.1 engine (`docs/specs/2026-10-23-v0.1-design.md`). This is the first v0.2
feature: the dataset importer named in that spec's §13 build phases.

## 1. Purpose

A `suite import` command that turns PyRIT's bundled **garak application-security datasets** into
our pack format, producing a standard OWASP-aligned **baseline** that runs against any endpoint
through the existing v0.1 pipeline. It establishes a common ground so every target — the lab bot
now, an organisation bot later — starts from the same checked set of prompts.

The importer is **tooling**. PyRIT's maintainers (and upstream, the garak project) authored the
prompts; this project authors the importer code and the dataset→OWASP mapping, never the attack
text. The prompt text moves file→file by machine and is never hand-written or transcribed here.
This keeps the hard rule: *Claude never writes attack prompts or planted injection text.*

### Goal for this feature
```
suite import --source garak --out prompts/baseline --canary SYSTEM-CANARY-7Q4P
suite run --endpoint endpoints/lab-bot.yaml --pack prompts/baseline --pack prompts/lab
```
The first command generates git-ignored baseline packs + `COVERAGE.md`. The second runs the
baseline plus the owner's own prompts, judged by the v0.1 deterministic pipeline, in one report.

### Non-goals
- **No harmful-content / content-moderation datasets** (garak `slur_terms_en`, the `airt/*` sets).
  Content moderation is a model-safety concern, not an application-security OWASP category, and it
  is not rule-judgeable without an LLM judge (ruled out in v0.1).
- **No multi-turn, no LLM judge, no load/soak testing.** Single-turn, reply-only, rule-judged —
  the same constraints as v0.1.
- **No automatic prompt-variation (converters).** That is a separate v0.2 item, not this one.

## 2. Key decisions (settled while brainstorming, 2026-10-26)

1. **garak application-security subset only** (Sahil's decision).
2. **Mapping table keyed by garak dataset name** — one row governs a whole file (Approach A).
3. **Generated baseline is git-ignored and regenerable**; the mapping table and importer code are
   committed. garak's attack text lives only in the PyRIT dependency, never re-distributed in our repo.
4. **`--pack` becomes repeatable** so the baseline composes with the owner's own prompts.
5. **Honest coverage:** LLM05/06/07/09 are rule-judged by dedicated datasets; LLM02 is an
   auxiliary `credential_leak` check on the extraction prompts; LLM01 is only *exercised* by those
   prompts (judged as LLM07 leakage — a dedicated LLM01 set needs the jailbreak templates, not in
   this subset); LLM03/04/08/10 are declared out of scope in `COVERAGE.md`, each with the reason.

## 3. Requirements

### Functional
- **F1.** `suite import --source garak --out <dir> [--canary <marker>] [--repeat N]` reads the garak
  datasets through PyRIT's own loader (behind `adapters/`), applies the mapping, and writes packs.
- **F2.** A committed mapping table: garak dataset name → OWASP category + deterministic check
  (a `must_not_contain` marker or a named detector) + default `pass_if` text.
- **F3.** Writes one pack file per OWASP category plus a `COVERAGE.md`. Output is deterministic
  (byte-identical on re-run) and written atomically.
- **F4.** The system-prompt-extraction prompts (filed under LLM07) always carry an auxiliary
  `credential_leak` detector. `--canary <marker>` additionally attaches `must_not_contain: [<marker>]`.
  Without `--canary`, the canary check is absent (the `credential_leak` detector still applies); if a
  prompt ends up with no check at all it goes to human review — never a silent Pass. (The v0.1 spike
  finding: extraction is only fully rule-judgeable against a planted marker.)
- **F5.** Wire `ShellCommandOutputScorer` and `PackageHallucinationScorer` into `pyrit_detectors()`
  so LLM06 and LLM09 are rule-judged (LLM09 pending the §10 verification).
- **F6.** `--pack` is repeatable on `run` and `validate`; the packs merge into one run and one report.
  A duplicate prompt id across packs is a `ConfigError` naming both files (reusing `load_pack`'s
  existing duplicate detection across the merged set).
- **F7.** Stable, deterministic prompt ids `BASE-<LLMxx>-<dataset>-NNN` (zero-padded, ordered by
  dataset then source position). Provenance (source dataset, PyRIT version, licence) lives in the id
  and a file header comment, so the v0.1 `Prompt` model is unchanged.

### Non-functional
- **N1.** Only `adapters/datasets.py` imports `pyrit`; `importer.py`, `importer_map.py` and the CLI
  import none. Enforced by the existing `tests/test_boundary.py`.
- **N2.** No attack text in the repo or the test suite. Tests use a small **benign fixture dataset**
  in garak file format, loaded through PyRIT's real loader.
- **N3.** `suite import` loads PyRIT lazily (it must read datasets); `validate`, `finalize` and
  `compare` stay PyRIT-free.
- **N4.** No network access in `import` or in the tests.

## 4. Architecture

```
suite import --source garak --out prompts/baseline --canary <marker>
      │
      ▼
src/suite/importer.py        orchestration (no pyrit import): applies the mapping, builds
      │                      Prompt/Pack objects, writes packs + COVERAGE.md, atomically
      ├─ reads → src/suite/adapters/datasets.py   the ONLY new pyrit-importing file: loads
      │                                           garak SeedDatasets via PyRIT's loader and
      │                                           yields (dataset_name, source, prompt_text)
      ├─ uses → src/suite/importer_map.py (committed)   dataset → OWASP + check + default pass_if
      ▼
prompts/baseline/  (git-ignored)   LLM05.yaml, LLM06.yaml, LLM07.yaml, LLM09.yaml, COVERAGE.md
                                   (one file per OWASP category that has a dataset row)
```

Four units, each with one job, reusing v0.1's `Prompt`, `Pack`, `Checks`, patterns and detectors:
- **`adapters/datasets.py`** — reads garak `.prompt` files via PyRIT's loader; yields each prompt's
  text + `source`/`dataset_name` provenance. Behind the adapters boundary, so a PyRIT rename touches
  one file.
- **`importer_map.py`** — pure data: `{garak_dataset: MapRow(owasp, check, default_pass_if)}`.
- **`importer.py`** — applies the map, groups prompts by OWASP category, writes the packs and
  `COVERAGE.md`.
- **`cli.py`** — a new `suite import` subcommand; reads datasets, writes files, sends nothing.

## 5. Mapping table (committed)

Each dataset gets exactly **one** OWASP category (the one we actually check), so each generates one
pack file.

| garak dataset (count) | OWASP (category) | Rule applied | Rule-judged? |
|---|---|---|---|
| `system_prompt_extraction` (28) | LLM07 | `must_not_contain: [<canary>]` + auxiliary `credential_leak` detector | ✅ with `--canary`, else → review |
| `web_html_js` (17), `example_domains_xss` (4) | LLM05 | detector `xss_output` | ✅ |
| `markdown_js` (7) | LLM05 | detector `markdown_injection` | ✅ |
| `access_shell_commands` (6) | LLM06 | detector `shell_command_output` | ✅ |
| `package_hallucination_{real,stubs,unreal}` (34) | LLM09 | detector `package_hallucination` | ✅ pending §10 |

The `system_prompt_extraction` prompts are injection techniques (LLM01) whose checkable outcome is
leakage (LLM07), so they are filed under **LLM07**; the `credential_leak` detector on them gives an
auxiliary **LLM02** check (a leaked secret Fails). A dedicated **LLM01** set would need the jailbreak
templates — out of this subset; a later `--source garak+jailbreak` can add it.

Excluded, with reason: `slur_terms_en` (hate speech — content moderation, not app-security);
`doctor`, `normal_instructions` (garak's own controls, no deterministic rule). ~96 prompts at
`--repeat 1` ≈ 96 attempts.

A prompt whose mapping has no deterministic check (or where `--canary` is absent) imports with its
`pass_if` text and no check, so it goes to human review — consistent with "Inconclusive / needs
review is never a Pass."

## 6. CLI

```
suite import --source garak --out prompts/baseline [--canary <marker>] [--repeat 1]
```
- `--source` is an enum (today: `garak`), so a later source is a value, not a new command.
- Prints `imported <N> prompts across <k> categories → <dir>`.
- Exit codes match the rest of the CLI: 0 ok, 2 for `ConfigError` (no traceback).

Multi-pack: `--pack` repeatable on `run`/`validate` — `--pack prompts/baseline --pack prompts/lab`.

## 7. Coverage statement (`COVERAGE.md`, generated)

- **Covered, rule-judged (dedicated datasets):** LLM05 Improper Output Handling, LLM06 Excessive
  Agency, LLM07 System Prompt Leakage, LLM09 Misinformation.
- **Partial / auxiliary:**
  - LLM02 Sensitive Information Disclosure — the `credential_leak` detector on the extraction
    prompts (not its own file).
  - LLM01 Prompt Injection — exercised by the extraction prompts but judged as LLM07 leakage; a
    dedicated LLM01 set needs the jailbreak templates (future `--source garak+jailbreak`).
- **Not covered by single-turn reply judging, with why:**
  - LLM03 Supply Chain — a dependency/provenance review, not a chat prompt.
  - LLM04 Data and Model Poisoning — a training-pipeline concern.
  - LLM08 Vector and Embedding Weaknesses — a retrieval-infrastructure concern.
  - LLM10 Unbounded Consumption — needs load/soak testing (v0.3+).

## 8. Error handling

Fail loudly; never a silent or empty baseline.
- Unknown `--source`, or a `--canary` too short for a `must_not_contain` entry (< 6 letters/digits)
  → `ConfigError`, exit 2.
- A mapped dataset missing, unreadable by PyRIT's loader (an upstream rename), or yielding zero
  prompts → `ConfigError` naming the dataset.
- Every generated prompt is run through the v0.1 `Prompt` validation before being written; a bad
  row surfaces with its dataset and index.
- Pack files and `COVERAGE.md` are written atomically (the evidence store's temp-file-then-replace
  pattern), so a crash can't leave a half-written baseline.

## 9. Testing (TDD, no network)

- `adapters/datasets.py`: tested against a **benign fixture dataset** (garak file format, placeholder
  prompts) loaded through PyRIT's real loader — deterministic, no attack text, no network.
- `importer_map.py`: a test asserts every row's category is a valid OWASP code and every referenced
  detector is wired in `DETECTOR_NAMES`, so the map and the registry cannot drift.
- `importer.py`: fixture datasets + map → expected packs (ids, checks, `pass_if`, header),
  byte-identical on a second run; `COVERAGE.md` lists the four uncovered categories; `--canary`
  attaches the check, its absence routes to review.
- `cli import` and multi-`--pack` merge (including the cross-pack duplicate-id error) get CLI tests.
- **Executed steps in the plan (not unit tests):** a spike confirming `PackageHallucinationScorer`
  runs offline-deterministic; an end-to-end `import → run` against the lab bot producing a report.

## 10. Risks / open items

- **`PackageHallucinationScorer` (LLM09):** it may need a package-ecosystem list (pypi/npm) and
  possibly network to confirm a package is fake. If it cannot run offline-deterministic, the LLM09
  row falls back to human review rather than a shaky rule, and `COVERAGE.md` records LLM09 as
  review-only. The plan verifies this in a spike before committing the row.
- **garak file-format stability** across PyRIT versions — mitigated by the `pyrit==1.1.0` pin; a
  format change is caught by `adapters/datasets.py`'s loud failure and its fixture test.

## 11. Build phases / validation

1. Spike: verify `PackageHallucinationScorer` offline-deterministic (§10).
2. Build the importer with TDD (components in §4 order).
3. **Executed validation:** `suite import --source garak` → `suite run` against the lab bot (canary

   (`prompts/lab/`, authored by Sahil) as the multi-`--pack` composition case.
